# Независимая разметка отзывов — пакет для Никиты

В партии 150 уникальных отзывов о женской одежде и аксессуарах из
Hplss/wb-review-dataset. Используется CC-BY-NC-SA-4.0; происхождение,
исходные ID и дата обращения сохранены в data каждого задания.
Основной текст, достоинства и недостатки объединены с подписями без
переписывания содержания. Звёзды и готовые ответы отсутствуют.

## Импорт

1. Активируйте окружение Label Studio и запустите `label-studio start`.
2. Откройте http://localhost:8080 и создайте отдельный проект отзывов.
3. Settings → Labeling Interface → Code: вставьте
   `labeling_interface_partner.xml` и сохраните.
4. Import → Upload Files: загрузите `review_tasks_partner.json` один раз.
5. Проверьте: 150 заданий без аннотаций. Размечайте по согласованному codebook.
6. Выберите ровно один класс и нажмите Submit для каждого отзыва.

Локальное хранилище и дополнительные серверы не нужны: тексты внутри JSON.
Не импортируйте одновременно отдельные JSON из data/reviews — это те же задания.

## Независимость и экспорт

`../review_markup_egor.json` содержит ответы Егора. До завершения своей
независимой разметки его не просматривайте и не импортируйте.
После завершения Export → JSON (полный формат, не JSON-MIN), сохраните как
`review_markup_nikita.json`. Сохраните data.sample_id и data.source_review_id.
Сопоставление выполняется по sample_id, а не внутреннему ID Label Studio.
Спорные случаи обсуждаются после сохранения двух независимых экспортов.

## Реестр

`../../reviews_registry.csv` содержит только принятую партию.
Поле candidate_class оставлено пустым: предварительные метки отбора
не восстанавливались из итоговых ответов. Исходные оценки в звёздах не включены.
sample_id назначены при подготовке пакета по возрастанию source_review_id.
В сохранённый экспорт Егора добавлено только data.sample_id; ответы и время
разметки сохранены. В действующей Label Studio эти ID не изменялись:
при следующем экспорте связь можно восстановить по source_review_id.
