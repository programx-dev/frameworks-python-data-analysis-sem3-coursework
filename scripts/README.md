# Запуск Label Studio и подготовка задач

Команды выполняются из корня репозитория.

## Запуск

В WSL:

```bash
bash scripts/start_label_studio.sh
```

Скрипт использует `~/tools/label-studio/.venv/bin/label-studio`.
Другую установку можно задать через `LABEL_STUDIO_BIN`.
Корень локальных файлов — каталог `data` этой копии репозитория.
Откройте http://localhost:8080. Для остановки нажмите Ctrl+C.
База Label Studio в WSL хранится отдельно: `~/.local/share/label-studio`.

На компьютере Никиты ранее исправлены `core/redis.py` и `server.py` установленного
Label Studio для ускорения запуска. Эти локальные исправления не входят в
репозиторий и могут быть перезаписаны при обновлении Label Studio.

В Windows, в окружении с установленным Label Studio:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_label_studio.ps1
```

## Подготовка и проверка задач

```bash
.venv/bin/python scripts/prepare_annotation_tasks.py
.venv/bin/python scripts/prepare_annotation_tasks.py --check
```

Скрипт проверяет общие sample_id, идентичность изображений и текстов, SHA-256
фотографий, классы и границы рамок. Затем создаёт только `data` без ответов:

- `data/tasks/images/image_tasks.json` — из разметки изображений Никиты;
- `data/tasks/reviews/review_tasks.json` — из разметки отзывов Егора.

Исходные экспорты не изменяются. `--check` только проверяет файлы.
Постоянные sample_id хранятся в `data` независимых экспортов;
отдельного реестра нет. При расширении выборки назначайте новые номера до
выдачи задач. Для изображений продолжайте после максимального существующего
номера; старые номера и пропуски не переиспользуйте.

## Импорт после изменения структуры

Создайте новый проект и используйте файлы из `data/tasks` по инструкции там.
Старые проекты Label Studio не меняются при редактировании JSON в Git:
их ссылки на фотографии из корня `data/images` после переноса в `birds` устарели.
Для восстановления своей разметки импортируйте в отдельный проект полный JSON
из `data/annotations/nikita` или `data/annotations/egor`.
Чтобы увидеть старые текстовые ответы Никиты в форме, используйте
`data/tasks/images/labeling_interface_nikita.xml`; для новой разметки подходит
общий `labeling_interface.xml` с готовыми сведениями об источниках.
Не импортируйте обе независимые разметки в один проект для повторной работы.
Для задач из JSON не подключайте дополнительно Sync тех же изображений.
