# Label Studio в WSL

Из корня репозитория:

```bash
bash scripts/start_label_studio.sh
```

Открыть http://localhost:8080 в браузере Windows. Терминал остаётся работающим,
для остановки нажать Ctrl+C. Перед запуском остановить предыдущий экземпляр.

Скрипт использует отдельное окружение `~/tools/label-studio/.venv`, включает
доступ к локальным файлам и задаёт корень файлов в каталоге `data` репозитория.
База проектов и аннотаций остаётся в `~/.local/share/label-studio`.
Путь проекта определяется по расположению скрипта. Автоматического
переименования фотографий нет.

## Исправление медленного запуска

В установленном окружении Никиты исправлены два файла пакета Label Studio:

- `core/redis.py`: подключение и `ping` Redis выполняются только при
  `settings.REDIS_ENABLED`. В Community Edition эта настройка выключена.
- `server.py`: проверка занятого порта ограничена одной секундой вместо ожидания
  системного сетевого таймаута.

Оригиналы лежат рядом с файлами с суффиксом `.before-startup-fix`.
Эти изменения внесены в установленный пакет. Bash-скрипт их повторно
не применяет. Обновление или переустановка Label Studio может перезаписать
исправления. Для другой установки путь к программе можно задать переменной
`LABEL_STUDIO_BIN`.

## Добавление фотографий через папку

1. Сохранять оригиналы в `data/images`. При использовании нумерации давать имя
   `IMG0002.jpg`, `IMG0003.png` и т. д., сохраняя расширение оригинала.
   Окончательное имя назначать до синхронизации.
2. Один раз подключить папку в проекте через
   **Settings → Cloud Storage → Add Source Storage → Local Files**.
   В **Absolute local path** указать полный Linux-путь к `data/images`.
   Выбрать **Files** или включить **Treat every bucket object as a source file**.
3. Для проекта, восстановленного из экспорта с 50 размеченными фотографиями,
   скопировать всю строку из `data/annotations/label_studio_new_images_filter.txt`
   в **File Name Filter**. Фильтр допускает JPG/JPEG, PNG, WebP, BMP, TIFF
   и исключает имена фотографий из экспорта
   `project-5-at-2026-11-15-10-45-e181c8b9.json` (включая исходные имена
   файлов, загруженных через Upload). JSON и Zone.Identifier не допускаются.
   Это фиксированный список исключений, а не проверка статуса разметки.
   Для текущих 50 фотографий предварительный просмотр должен быть пустым.
   **Scan all sub-folders** оставить выключенным.
   Дальше использовать одно и то же подключение Storage и сохранять имена
   файлов: синхронизация учитывает уже добавленные через это подключение объекты.
   Не добавлять те же фотографии параллельно через Import или другое Storage.
   Переименованная копия фотографии не распознаётся фильтром как дубликат.
4. Проверить соединение и нажать **Save & Sync**. После следующих скачиваний
   нажимать **Sync** у этого хранилища, затем обновлять таблицу заданий.
5. Открыть новый кадр, заполнить URL страницы файла, автора и лицензию,
   обвести каждый объект соответствующей рамкой `bird` или `drone`, нажать
   **Submit**.

После синхронизации сохранять имена и расположение файлов: задания ссылаются
на них напрямую. Источник, автор и лицензия заполняются в форме. Дату и время
аннотации, а также `lead_time` сохраняет Label Studio. Экспорт полного JSON
сохраняет эти сведения и результаты разметки.

Встроенный **Sync** запускается вручную. Для появления заданий сразу после
скачивания нужна дополнительная автоматизация через API.

## Подготовка фотографий для независимой разметки

Из корня репозитория:

```bash
.venv/bin/python scripts/prepare_image_partner_package.py
```

Скрипт читает `data/annotations/image_markup_nikita.json`, добавляет числовой
`data.sample_id` и переносит источник, автора и лицензию также в `data`.
Существующие аннотации, внутренние ID, авторство и время разметки сохраняются.

Соответствие фотографии и номера записывается в
`data/annotations/image_sample_ids.json`. Этот реестр нужно сохранять:
повторный запуск использует прежние номера, новые фотографии получают следующий
свободный номер. Проверка SHA-256 защищает от замены изображения под прежним ID.

Готовый архив для другого компьютера:
`data/annotations/aod4_partner_package.zip`. Внутри находятся фотографии,
`image_tasks_partner.json`, XML интерфейса, инструкция и скрипты запуска
для Windows и Linux/WSL. Готовых рамок в архиве нет.

Отдельные файлы импорта находятся в `data/annotations/partner_images`.
Сведения об источниках отображаются готовым текстом и экспортируются в `data`;
напарник самостоятельно рисует рамки. Он импортирует JSON один раз в новый
проект и не синхронизирует те же фотографии через Cloud Storage.

После нового экспорта из проекта Никиты, если в нём ещё нет `sample_id`, нужно
снова запустить этот скрипт: номера будут восстановлены из общего реестра.
